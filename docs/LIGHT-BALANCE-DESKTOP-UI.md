# 明暗与白平衡：桌面0.2.5开发版

## 用法

导入照片后，在右侧基础调色下面展开“明暗与白平衡”。阴影和高光范围各为 -100～100，默认0。它们是全局平滑亮度曲线，不是人脸专属美颜。重置整组恢复中性；“重置白平衡”只将RGB增益复位为1，不清除明暗或其他调节。每次有效改动可撤销、重做。

点击“中性区域吸管”会临时显示这一处理阶段的输入：已有点修、肤质和基础调色仍生效，而当前明暗/白平衡、后续色阶/曲线/局部/手动变形、背景、最终构图、留白和文字不参与取样。界面明确标记该输入视图。选择画面中本应中性的灰色或白色物体，不能把皮肤当白点。若上游肤质开启却缺少实际人脸事实，先完成该照片分析再取样，不能假装该效果已经参与。

吸管读取鼠标点附近的有界方形区域，而非单个噪声像素。过暗、过曝、半透明、有效像素不足或明显混色时会说明拒绝，保持原设置。成功后只保存RGB增益，不保存点位、照片或路径到预设。按Esc/取消，拖动、第二指针、焦点丢失、照片切换、撤销、比较切换或过期渲染都不会留下半次编辑。缩放/平移会取消待提交的点；可以重新点击有效的新鲜帧。

## 历史、工程、命名预设和批量

固定顺序：点修 → 肤质 → 基础调色 → 明暗/白平衡 → 色阶 → 曲线/HSL → 后续局部/手动/背景/构图/文字。取样使用这个顺序中明暗阶段之前的实际像素；不从最终视觉结果反向猜测。

工程v10读取旧v1–9，缺省新组为中性。已有、撤销、重做、已提交和导出状态均保存严格校验的新组。旧0.2.4最高读取v9，不能读取新v10工程，需保留旧文件备份。

命名预设v3包含人像、基础调色、明暗/白平衡、色阶、曲线/HSL五组；旧v1/v2迁移时不丢已有组，新组中性。文件依然不含照片、路径、蒙版、笔画、几何、点位或人脸事实。预设与参数同步可以批量复制这组数值，不代表自动为每张照片重新寻找白点，也不说明不同灯光照片适合完全相同增益。旧不支持v3的应用应明确拒绝，不可静默跳过。

## 数值和质量边界

线性光白平衡先作用，再通过单调亮度曲线调整阴影/高光。RGB按共同倍率缩放；超色域时再共同归一，避免单通道独立裁切与向白混合的灰雾。在色域内保持校正后线性RGB比例；色域外不能同时保留目标亮度，已经满幅的饱和原色也不能无限提亮。

这里并不承诺感知饱和度、HSL色相或亮度完全不变。强参数会明显改变反差与观感，极端相对增益仍会放大8位量化台阶。默认中性，不将强阴影提亮设为自然美颜预设；纯白/纯黑中已经丢失的信息无法恢复。显示与取样是8位sRGB缩小预览，不是RAW、高位深、Kelvin色温测量、自动肤色识别或学习型修图。

旧向白混合候选在公开肖像的+25就产生灰雾，已明确否决。负控代码、图片和数值单独留在QA，不作为隐藏fallback。新候选的两个肖像对照只能说明该具体缺陷改善，不能代替多肤色/灯光的美感盲评。

## 实际验证与未验证

- 零值/默认保持同一输入对象和每个RGBA字节；活动结果不修改原图，alpha和完全透明隐藏RGB保持。最终透明PNG的隐藏RGB清零仍是独立的既有隐私导出规则。
- 有效/无效取样、真实前置阶段像素、画布映射、取消、过期帧、历史、项目/预设迁移、导出均有本机代码和NativeCanvas/Sharp测试。
- 两张公开肖像的11份原尺寸native PNG输出回读与共享核心一致；受控灰卡实验平均RGB误差9.34→0.414、最大2码值。这是人工已知色偏，不是对真实现场照明的测量。
- 897×1000公开样片的五组活跃配方，通过分阶段、实际native导出和源字节不变检查；两端复跑记录另见five-groups-parity.json及移动端对应报告。
- 云端Node/NativeCanvas/Sharp不是真实浏览器、Electron窗口、Windows、Android设备、4060速度或色彩管理显示器验收。未发布新安装包；0.2.4交付不变。
