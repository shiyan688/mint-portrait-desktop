# 逐人修饰：开发候选说明

这项能力尚未进入已交付的 0.2.5 安装包。它扩展选脸和独立参数工作流，不代表学习型修肤、身份识别或 SOTA 美颜验收。

## 使用方式

1. 导入照片，在人像参数前的“逐人修饰”展开项中启用。最多记录 5 张脸，编号仅属于此次检测，不会在照片之间追踪身份。
2. 先明确选择人物，再使用现有修肤、色调、唇色/腮红、眼鼻和脸型滑杆。默认所有人参数为零。人物框检查显示原始照片与原始坐标，不是已变形效果上的跟踪框；调参数会退出原图检查。
3. 每个人从同一阶段的不可变输入产生效果，而不是先变形第一人再拿旧坐标改第二人。相邻影响区或采样区相交会拒绝此次操作，不会靠硬裁剪或混合缝偷改邻人。
4. 重新检测会建立新的全零批次，不按旧编号继承参数。若已有修饰会先询问；成功是一个可撤销动作。取消只阻止迟到结果生效，不宣称立即中断同步 WASM 推理。
5. 工程保存包含网格和参数，重开无需再次检测即可回放；不会自动替你选人。撤销、重做、停用、重置当前人物均保留原件。

## 明确的边界

- 此阶段使用已包含的 MediaPipe Face Landmarker 做几何分析，实际修肤/色彩/变形仍是已有传统可调处理，不是新的学习型修肤模型，也不宣称保留所有皮肤纹理。
- 新逐人模式的眼睛/瘦脸范围为 0–60，鼻子/下颌为 -50–50；这不改变旧工程全局控件含义。效果默认为零，不统一漂白或推断族裔。
- 逐人塑形与手动液化不能并存，透明输入或透明背景后的塑形被拒绝。冻结选区的最终绘画/遮挡层不支持逐人变形后的选区映射；已有层的几何绑定改变也会拒绝，不会悄悄丢层。
- 开启逐人修饰效果的处理阶段最多 1600 万像素、单边 16384，还受每阶段额外估计 256 MiB、累计 typed-array 分配 512 MiB 和 5 亿 workUnits 限制。复杂组合可能在更小尺寸拒绝。以上不是实际进程 RSS 或 GPU 显存保证。
- 全零批次不让原本支持 6400 万像素的普通调色导出降成 1600 万。小裁剪、留白或最终缩图不能绕过原始处理上限；选择工作尺寸是明确降分辨率，不自动替换原尺寸选项。
- 配方文件只带所选人物的美颜数值，不带网格、批次编号或照片信息。完整配方仅能应用于当前明确选中的人物；对多张照片批量使用需选择仅调色。参数同步保留每张目标照片自己的逐人批次，不复制人物身份或坐标。
- 项目版本 13 读取版本 1–12；旧程序不保证能打开新项目。项目仍保留原图和编辑历史，不能当成已脱敏照片分享。网格随历史保存，项目 JSON 的 16 MiB 上限未放宽；过大时拒绝保存并保留旧文件，不静默删历史。

## 本轮证据与未验收项

公开 NASA 成人照片的 2 人和 5 人合成拼图，使用已有 Python CPU MediaPipe 0.10.21 检测结果进行像素回放。它们不是实拍合照、产品素材、商业肖像授权、人物背书或训练集。所选人与邻人的不变性、顺序无关、真实 PNG 编解码以及 Worker/native 渲染一致性有自动检查。

UI 检查执行当前 app 代码、作者编写的 DOM 测试环境和实际 NativeCanvas；不等于 Chromium、Electron、Windows、Android 或用户 4060 实机验收。真实合照的遮挡、侧脸、密集人群、肤质观感和性能仍未获得普遍质量结论。
