# Dedicated portrait retouch research and implementation decision

Verified 2026-10-21. Read-only primary-source research; no new model was executed, no model terms were accepted, and no photo was uploaded. This report does not certify any method as universally best. The existing handcrafted defect repair remains an unreleased baseline.

## Recommendation in one page

- **Best evidenced recent specialized candidate found: BeautyGRPO (CVPR 2026 Highlight).** Evaluate it as an optional high-quality retouch backend only after base/adapter rights and available memory are resolved. It is not a ready, permissively redistributable RTX4060 product.
- **Most concrete permissively labelled deployable dedicated baseline found: Alibaba ModelScope `iic/cv_unet_skin_retouching_torch`.** It has actual official skin-blend, blemish-detection/inpainting, skin-mask and face-detector files, with a model card declaring Apache 2.0. It is based on older ABPN-era ideas, NOT 2026 SOTA. Treat as an explicit comparison/fallback candidate, never quietly substitute it for a promised leading model.
- **RetouchGPT / RetouchFormer:** useful dedicated comparisons, but unresolved checkpoint/dependency rights and brittle public entrypoints prevent a ready-to-bundle recommendation. Newer is not automatically deployable.
- **Tone enhancement is a separate task:** InstantRetouch's bilateral rendering is attractive for structural fidelity but released trained checkpoints were not found. VeraRetouch has checkpoints but restricts them to academic research. Neither is a replacement for dedicated blemish removal.
- Keep full-resolution original, semantic edit masks, feature/occlusion protection, explicit model provenance, bounded strength, undo, and fail-closed errors outside the learned backend. A model name alone cannot prevent destructive resizing or silent fallback.
- Personal non-commercial use versus commercial distribution, offline-only versus separately approved API processing, and exact GPU/RAM determine which route is feasible. Personal use does not grant absent author permissions. No paid API, private-photo transfer or gated-model acceptance is authorized by this report.

## 1. BeautyGRPO: leading specialized research candidate, constrained deployment

The paper evaluates 1,000 FFHQR and 1,000 in-the-wild portraits, with six no-reference quality/aesthetic metrics plus ArcFace/FID. Its 100-person, 20-case preference study reports 63.25% preference. Importantly, identity is NOT best across all methods: FFHQR ArcFace is 0.952 versus RetouchFormer 0.986; in-the-wild 0.944 versus 0.976. This is a perceptual/fidelity trade-off, not a universal win. Experiments use eight H20 GPUs; that does not establish a single-card inference minimum or RTX4060 latency. [Primary paper](https://arxiv.org/html/2603.01163v1)

The author README states MIT for the project and reports released LoRA weights, FLUX.1-Kontext-dev base, 1024 output and 28 denoising steps. A later exact-tree audit at commit `80fcf466d6bfc3b3a05e1cbedd11e3a3ced2bcb9` found that the referenced LICENSE and requirements.txt are absent. Treat MIT as the README declaration, not a verified complete license file. The README explicitly separates code and pretrained-weight licenses; the LoRA repository lacks a license/model-card grant. These gaps must not be treated as resolved permission to redistribute. [Official repository](https://github.com/vivoCameraResearch/BeautyGRPO)

Actual HF metadata was independently read: commit `241d57903834ba55cb544b665686eb5d494b3dcf`; required LoRA is `fluxkontext/checkpoint/pytorch_lora_weights.safetensors`, 179,400,528 bytes, LFS SHA-256 `23105cbd94fcd9f7b14d224dd28ce84cb5fa0f9bd5ba077cc0de27428e46c8a1`. The repository also contains optimizer/reward-model material that inference must not download unnecessarily. No README/license card was present at the checked model endpoint. [Official model metadata](https://huggingface.co/api/models/Sehnsucht24/BeautyGRPO), [file metadata](https://huggingface.co/api/models/Sehnsucht24/BeautyGRPO/tree/main/fluxkontext/checkpoint?recursive=true&expand=false)

The base is 12 billion parameters and gated behind explicit agreement to the FLUX dev non-commercial license and sharing Hugging Face account information. Output commercial use and commercial model use are distinct. No agreement was accepted. A rough 12B×2-byte BF16 parameter estimate is 24 GB before text encoders/activations, not a measured memory requirement; the raw implementation cannot be assumed to fit an 8 GB-class card. Quantization/offload would be a separate unvalidated adaptation. [Base model and access conditions](https://huggingface.co/black-forest-labs/FLUX.1-Kontext-dev), [official license](https://github.com/black-forest-labs/flux/blob/main/model_licenses/LICENSE-FLUX1-dev)

Code audit finds two product hazards: failed LoRA loading continues with the base model, and non-square photos are directly resized to a square. A production adapter must reject failed or missing LoRA, verify its exact hash, preserve aspect ratio and source-coordinate ROI, protect non-target pixels, and report the actually loaded backend. Do not execute this script unchanged. [Official inference source](https://github.com/vivoCameraResearch/BeautyGRPO/blob/main/src/inference/infer.py)

## 2. Practical learned baseline: ModelScope skin retouch

The official model card declares Apache License 2.0 and describes UNet blend-map skin equalization, blemish localization/inpainting and skin segmentation/whitening. It recommends faces over 100×100 pixels, total image below 5000×5000, and 512-pixel face/body inference crops pasted into the original. The hosted inference specification lists 16 GB GPU memory; this is NOT proof of a 16 GB minimum or of 4060 feasibility. Training is limited and unusual images/small subjects may fail. The card explicitly includes moles among removal targets, so automatic full-strength use conflicts with conservative identity-feature preservation. [Official model card](https://modelscope.cn/models/iic/cv_unet_skin_retouching_torch/resolve/master/README.md)

The author-linked ModelScope wrapper uses ONNX for skin segmentation and PyTorch for local retouch, but old pickle-loading paths and automatic face-detector resolution require a constrained local adapter, reviewed code and safe weight loading. Avoid wholesale dynamic remote-code execution, hidden downloads, forced whitening and changed default mole removal. [Official wrapper](https://modelscope.cn/models/iic/cv_unet_skin_retouching_torch/resolve/master/ms_wrapper.py), [maintained pipeline source](https://github.com/modelscope/modelscope/blob/master/modelscope/pipelines/cv/skin_retouching_pipeline.py)

ABPN is a CVPR2022 high-resolution local-retouch method. Its author repository links ModelScope application models but says those leverage the blend-layer concept, not that they reproduce every paper result. CRHD-3K dataset is non-commercial research only, distinct from the ModelScope model card. Do not bundle the dataset or equate dataset and model terms. [Author repository](https://github.com/youngLBW/CRHD-3K), [paper](https://openaccess.thecvf.com/content/CVPR2022/papers/Lei_ABPN_Adaptive_Blend_Pyramid_Network_for_Real-Time_Local_Retouching_of_CVPR_2022_paper.pdf)

## 3. Other dedicated candidates, and why not the default yet

- **RetouchGPT, AAAI2025:** real interactive imperfection-prompting method, official code MIT, author-provided `gen_best.pth` Baidu link. The current test script uses an invalid argparse action, a 512px default and different checkpoint naming. The model additionally expects T5 and Vicuna paths, loads the latter float32 on CUDA, and does not establish a complete redistributable dependency/weight license stack. No 4060 memory or latency measurement found. This merits a later reproduction, not an immediate packaged promise. [Repository](https://github.com/Davidcoach/RetouchGPT), [license](https://github.com/Davidcoach/RetouchGPT/blob/main/LICENSE), [model source](https://github.com/Davidcoach/RetouchGPT/blob/main/model/RetouchGPT.py), [test entry](https://github.com/Davidcoach/RetouchGPT/blob/main/test.py)
- **RetouchFormer, AAAI2024:** imperfection prediction and selective attention, with an author-provided checkpoint. Its GitHub API reports no license and root LICENSE is absent. Public code/weight availability is not redistribution permission. [Official repository](https://github.com/Davidcoach/retouchformer_aaai_24), [paper](https://ojs.aaai.org/index.php/AAAI/article/view/28404)
- **Face Retouching with Diffusion Data Generation and Spectral Restorement, ICCV2025:** dedicated FSR/MRF method with 25,000 before/after pairs, explicitly targeting global consistency and fine details. Official paper page is accessible, but no verified author-linked downloadable model/code release was located. The PDF endpoint returned403 in this research run. Keep as literature comparison, not an implementable delivered model. [CVF primary page](https://openaccess.thecvf.com/content/ICCV2025/html/Xu_Face_Retouching_with_Diffusion_Data_Generation_and_Spectral_Restorement_ICCV_2025_paper.html)
- **CGFR, ICME2024:** physics-based gradual blemish adjustment in melanin/haemoglobin space, preserving a separate texture layer. Useful controlled-edit design, not a universal neural SOTA replacement; verified code/weights release was not located. [Primary paper](https://arxiv.org/html/2406.13227v1)

## 4. Tone/color: preserve structure, separate from blemishes

**InstantRetouch, CVPR2026:** one-step instruction-conditioned bilateral-grid affine color transformations applied to original pixels. The paper reports 4K processing in68ms, but no4060 benchmark was verified. The operation is tone/color retouch, not texture inpainting. Code is Apache2; README checkpoint instructions only reference results from one's own training, and no downloadable trained checkpoint was found in the checked repository. Do not present it as ready offline skin cleaning. [Official repository](https://github.com/OpenImagingLab/InstantRetouch), [paper](https://openaccess.thecvf.com/content/CVPR2026/papers/Wu_InstantRetouch_Efficient_and_High-Fidelity_Instruction-Guided_Image_Retouching_with_Bilateral_Space_CVPR_2026_paper.pdf)

**VeraRetouch, SIGGRAPH2026 conditional-accept label in repository:** released reasoning and reference-retouch checkpoints, encoder-renderer path, chunking for large images, plus CoreML demonstrations. Code Apache2 but weights and derivatives explicitly academic-research-only; commercial use is prohibited without author permission. It is a promising efficient color/style route, not a permissive commercial blemish engine. [Repository and weight links](https://github.com/OpenVeraTeam/VeraRetouch), [separate license terms](https://github.com/OpenVeraTeam/VeraRetouch/blob/main/LICENSE)

## 5. Measurable acceptance plan, proposed not completed

1. Freeze a permission-cleared held-out portrait suite with varied visible skin appearance, lighting, noise, makeup, occlusion, hair, glasses, pose and multiple faces. Keep the existing three NASA examples as negative-control regression, not sufficient coverage. Do not train on tests or publish private photos.
2. Render exact originals at 0/25/50/100, single controls and combined controls, at preview and full output resolution. Include skin/neck/hand continuity and protected moles/freckles chosen by the user. Same crop, color handling, mask and output scale for all methods.
3. Hard invariants: byte-exact zero-strength result; immutable original; untouched alpha unless the task changes it; identical pixels outside authorized mask/ROI; no fallback labelled as the selected model; original dimensions/aspect ratio; no unexpected face geometry in a skin-only operation.
4. Inspect native-size pores, hairline, eyelids, brows, lips and neck boundaries. Evaluate blemish reduction only inside annotated blemish regions and preserve non-blemish skin texture outside them. Report edit-boundary gradient, chroma/luminance changes, clipping, masked reconstruction error, texture-band energy and protected-feature displacement. Do not optimize merely for changed pixel counts.
5. Use perceptual/identity metrics only with verified licensed metric weights and matching published evaluation protocols. An identity similarity score is supporting evidence, not proof that every unique feature survived. Do not compare different crops/splits/metric variants as a single SOTA leaderboard.
6. Blind before/after preference review judges naturalness, texture, unwanted changes, edit intent and recognizable identity, not people's attractiveness. Require zero obvious face plates, halo seams, unintended feature removal or non-target edits. Document failure cases, not only best examples.
7. On authorized target hardware: record exact GPU/VRAM, drivers, RAM, model hashes, dtype/quantization, peak VRAM/RAM, cold load, per-image p50/p95 latency and cancellation behavior. Test one-face, five-face, portrait orientation and long-edge4096 workloads. Quantized/offloaded variants must pass their own quality comparison.
8. Release gates are not met until actual Windows install/launch/export/uninstall, privacy/offline behavior and the visual suite pass. The generic backend scaffold and classical repair cannot be shipped as a completed SOTA overhaul.

## 6. Safe work possible before model choice

Prepare an injected, typed backend contract, fail-closed model registry, original-coordinate ROI extraction, immutable-source guard, explicit mask composition, bounded strength, cancellation/stale-result rejection and provenance records. Add only test doubles clearly marked as such. No trained adapter is advertised as ready. Model loading, optional downloads, license acceptance and performance tuning remain gated on the user's route and verified model rights.
