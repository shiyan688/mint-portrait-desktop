# 最终文件尺寸：桌面0.2.4开发候选

## 入口与行为

顶部“导出照片”打开队列。先选择“处理基准”：原尺寸或工作尺寸（最长边4096），再选择“最终文件尺寸”。默认“保持处理后的尺寸”精确中性；“指定精确长边 · 仅缩小”接受1至16384的整数像素。显示尺寸已包含最终构图与留白；若一张照片的合成长边小于目标值，该项明确失败，其他照片继续，不放大、不擅自换另一个目标值。

目标是完成整个合成后缩小副本：原图/工作尺寸解码 → 效果及手动历史 → 最终裁剪/旋转/翻转 → 四边留白 → 文字 → 最终缩小 → PNG或JPEG编码。文字保持所选处理基准的排字，不在较小输出上重新换行。PNG保留透明度并清除量化alpha为0的隐藏RGB；JPEG在缩小后填充白底。

“工作尺寸”不是最终文件尺寸。工作尺寸会先缩小源图再执行效果；即使指定很小的最终文件，原图模式仍先按原图重放。源图、复杂操作、文字和所有中间画布预算照常检查；小输出不绕过它们。8-bit sRGB不代表RAW、16-bit或宽色域工作流。

## 状态与安全

- 这两个导出选项不改变图片历史、项目、预设或恢复草稿，不重画编辑画布。窗口中的比较与字体预览仍是处理基准预览，不是压缩后输出样张。
- 开始队列时拍摄选项快照，运行期间禁用尺寸控制。失败重试沿用原队列快照，而非读取后来改过的表单。
- 取消、关闭页面、旧版本结果或错误尺寸不会写出。原始照片不覆盖，写出沿用临时文件和原子不覆盖提交。
- 本地服务根据已验证源图和配方自行重算处理、合成、最终尺寸，拒绝伪造结果。活动文字栅格绑定的是缩小前合成尺寸、源图哈希、版本和文字配方哈希，不接受以最终小尺寸冒充排字基础。
- 最大基础画布64MP/16384边；复杂/活动文字合成16MP，源输入和输出文件各80MiB。尺寸规划中的RGBA内存数只是该阶段输入/输出估算，不是整个应用的峰值内存保证。

## 验证边界

桌面正式导出使用已固定的Sharp0.35.5/Lanczos3；独立Canvas备用路径使用浏览器高质量采样。这两种采样不承诺相同像素。手机采用相同正数half-up尺寸语义，但其内存与边长预算更小，不复用桌面预算。

真实Linux Native Canvas字体合成与Sharp PNG/JPEG解码证明全合成后缩小；作者DOM事件桩验证表单、冻结队列、重试和取消。不代表浏览器、Electron、Windows安装或Windows系统字体实测。详见 EXPORT-SIZE-DESKTOP-CONTRACT.md 与 EXPORT-SIZE-INDEPENDENT-QA.md。
