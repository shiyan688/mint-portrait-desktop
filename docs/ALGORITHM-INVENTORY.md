## Actual non-learned operations

1. Skin smoothing: normalized local box convolution of skin-weighted samples; color-residual-based edge preservation; original detail retained by bounded blend. Candidate uses soft inward distance ramps, feathered eye/brow/lip exclusion, continuous warm-chroma confidence and face-relative shadow protection. The old shipped baseline hard-clipped its feathering and is rejected by new regressions. This is not a semantic skin parser, blemish model, frequency-separation network or learned high-end retouch model. Colored illumination, makeup, very small/occluded/profile faces and unusual hair/skin overlaps remain unvalidated.
2. Skin brightness: candidate applies bounded common RGB gain in linear light, anchored shadows and highlight roll-off, about 0.40 EV maximum before spatial/confidence reduction. It does not whiten with an opaque color layer. Warmth is bounded chroma adjustment with luminance normalization. Neither operation has a neural model.
3. Blemish brush: two rings of local samples, robust brightness selection, least-squares RGB plane, feathered circular blend. Up to 64 explicit user-selected spots. No texture synthesis, patch search or diffusion inpainting. Large marks and complex texture can look flat.
4. Reshape: MediaPipe anchors drive compact elliptical displacement fields for cheeks, jaw, eyes and nose. Total displacement capped at 12% of smaller face dimension, premultiplied-alpha bilinear resampling. No 3D identity-aware geometry or learned warp. Nearby background also moves; overlapping multiple faces can interact. No guarantee of identity/perceptual preservation at extreme settings.
5. Background: probability-alpha compositing for color/transparent modes; bilinear confidence resize, outward feathering, background-only normalized box blur. No learned matting refinement, defringe, foreground color decontamination, depth-aware lens blur or background generation.
6. Global tone: mathematical linear-light exposure, perceptual RGB contrast, luminance-based saturation, simple red/blue temperature shift. These controls need a correct color pipeline, not an unsubstantiated SOTA label.
7. Decode/export: browser 8-bit sRGB canvas, JPEG/PNG/WebP import and JPEG/PNG UI export. Maximum 4096-pixel long edge / 16 MP; no RAW development, 16-bit workflow, ICC proofing, EXIF retention, restoration, deblur, super-resolution, relighting or generative-image model.

## Integration boundaries to retain

- `src/pipeline.js`: `initModels`, `decodeImage`, `analyze(canvas) -> {landmarks, mask, faceCount}`, `render`, `encode`, `cancelRenders`. Landmark/mask analysis must stay linked to source coordinates, cached per immutable original. Failure must be explicit, not a fabricated face or ellipse.
- `src/pixel-worker.js`: current deterministic stage order is heal -> skin -> global tone -> background -> geometry. Faces are max-unioned before one skin pass. Real-fixture worker equivalence tests protect against drift between standalone engine and desktop integration.
- `src/portrait-engine.cjs`: five pure functions `beauty`, `heal`, `reshape`, `warp`, `background`. RGBA8 input/output contract, dimensions preserved, no input mutation, alpha contract explicit. This remains a baseline/reference or safe fallback only, not a mislabelled learned backend.
- A higher-quality local native backend can be introduced behind the render/analyze contracts, with explicit model/task/version/hash, async request/cancel, source-coordinate masks/warps, bounded memory, measured performance and feature capabilities. It must not silently fall back while claiming the selected model ran.
- Model-specific policy: verify official weight/code provenance, redistribution/usage terms, license compatibility and download integrity before use. Do not upload photos or introduce keys/paid APIs. Large optional model packs should be separately versioned, not hidden inside a small installer promise.
- Preserve desktop security boundaries, native import/export permissions, exact-origin IPC, no external image requests, read-only originals, collision-safe output names, undo/settings state, cancel behavior and installer 0.1.1 path safeguards.
- Keep Android and desktop behavior aligned at task/API level, but select suitable execution/quantization per platform only after actual quality/performance comparison. An RTX 4060 report alone does not establish available VRAM, driver state or mobile acceleration.

## Evidence and limits

The later approved research execution produced real SegFace parsing on three public fixtures and real BiRefNet HR alpha on public fixtures. SegFace's original-ROI diagnostic path is enabled in the candidate source; dedicated skin retouch remains absent. BiRefNet is not released as quality-accepted because hard garment/edge cases fail visual review. Official cloud CPU runtime is Python 3.12.14, torch 2.14.1+cpu, torchvision 0.29.1+cpu with CUDA unavailable. This is not an RTX 4060 benchmark. `desktop-backend.cjs`, `desktop-ai.cjs` and the model/device dialog provide local process/IPC/status boundaries; generative adapters remain disabled and unwired. See the checkpoint, `DESKTOP-BACKEND.md`, `SEGFACE-INTEGRATION.md` and `GENERATIVE-BACKENDS.md` for exact limits.

The defect-mitigation working tree passed 185 Node tests (including 82 NSIS instruction-model tests with mocked native APIs). Three public NASA portraits were processed using genuine locally inferred MediaPipe landmarks and actual JS pixel code, with old/repaired comparisons at brightness 0/25/50/100, max smoothing and warmth. See `SKIN-VISUAL-QA.md` for final evidence and exact scope. Three images are a regression demonstration, not an all-population quality benchmark. No native Windows install/launch/uninstall or browser-WASM end-to-end test has passed in this cloud run. No claim of state-of-the-art performance is supported by this baseline.
