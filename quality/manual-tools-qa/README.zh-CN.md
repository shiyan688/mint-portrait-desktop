# 手工选区、液化与纹理修补：独立验收记录

检查日期：2026-10-22。范围是当前候选核心与云端原尺寸 PNG 导出，不是 Windows/Android 设备验收，也不是 SOTA 证明。

## 已验证的结论

早期手工工具检查点：62 项独立自动测试通过，0 失败、0 跳过。历史运行记录：`independent-tests.tap`；历史源码哈希：`tested-source-hashes.json`。本轮最新88项见文末增量，不覆盖改写历史。

- 选区：画笔、套索、按顺序加减、羽化、反选；空选区与不限制选区严格区分。退化套索拒绝。不同尺寸按原图归一化位置重新栅格化。
- 液化：推笔、局部还原、每笔选区快照；选区零权重处逐字节不变，alpha 不变；整笔取消不修改输入。覆盖全部位移支撑区的还原能逐字节恢复输入。128 条交叉推笔仍满足保守邻边位移梯度限制；这不等于人像审美不变。
- 输入事件密度：同一直线 2 与 101 点液化输出及工作量一致；修补 2 与 501 点输出一致，避免慢拖动因鼠标频率改变强度。
- 修补：同笔从不可变输入取样，不沿笔划产生反馈拖尾；仿制必须手动选源。自动取样拒绝眼、眉、唇、脸边界及附近校准区；明确手动仿制仍可修这些位置。
- 修补的硬/软/空选区、选区外像素及 alpha、越界供体、取样重叠、过大/过长笔划、取消与照片版本过期均有测试。超限拒绝，不静默截短，不把模糊涂抹当纹理修复。
- 选区转局部色调层：零权重像素不变、羽化与图层 opacity 只相乘一次、已保存快照不跟随之后的选区修改。只显示当前选区不影响导出。
- Worker 脚本与原尺寸导出核心的局部色调+仿制结果逐字节相同；实际 PNG 编解码后也与重放像素一致，源文件字节不变。状态级撤销/重做重放不重复累积效果。

## 肖像视觉证据

仅用一张已有公开成人职业肖像，出处和使用边界见 `fixtures/PROVENANCE.json`。它不代表各种肤色、年龄、拍摄条件或真实瑕疵。

1. `public-portrait-synthetic-dot-contact.png`：5 处人工叠加的孤立深色小点，附原图/合成输入/修复。不是人物真实痘痘。对应早期修补候选哈希与数据保留在 `real-synthetic-dot-results.json`。
2. `synthetic-skin-variants-contact.png`：柔和红色覆盖、三点簇、混合明暗三种明确合成覆盖。配套 `synthetic-skin-variants.json` 和 `synthetic-skin-diagnostics.json`。
   - 红斑/红点簇的低频色度残差降低约 85%/83%；纹理高通 RMS 约为原图的 91%。
   - 同时引入约 +4.3–4.6/255 的局部亮度偏差。混合明暗例原本几乎无色偏，补片引入少量色偏。
   - 边界新增亮度梯度 P95 约 2.29/255；查看放大图未见明显硬缝，但不能据此保证所有半径或场景。
   - 逐像素 MAE 改善仅 2.2%/21.4%/30.9%，因为合法替换纹理也改变像素。不能把该比例解释为去红比例，也不能仅凭它验收质量。
   - 上述是明确给出定义的自定义诊断指标，不是校准过的感知评分、临床指标或 SOTA 基准。
3. `natural-selected-mark-contact.png`：测试者在原图选择一个小自然色差点，对比手动选源修复与原样仿制。没有叠加缺陷，没有真实理想结果；不诊断该点为痘痘，不宣称应该消除。修复/仿制分别改变 119/120 个像素，笔刷外 0 改动。

## 已封口的组合缺陷与尚未覆盖的发布条件

- 旧版本液化后用旧人物蒙版换背景会失配，曾有 96 个被推出的合成主体像素被误裁透明。历史记录 `stale-matte-failure.json`。现已明确拒绝此组合，经过 Worker、导出核心、设置验证与格式/哈希均有效的导入项目逐层复测；没有自动同步蒙版这一功能。
- 液化后原脸部点位可能过期。现明确拒绝叠加旧自动塑形和自动取样修复；明确手动取样仍允许，并已验证 Worker/导出结果一致。当前没有自动重新定位已液化人脸的能力。
- 现有自动保护依据人脸几何，不是头发/胡须/遮挡分割。脸内刘海、胡须、手遮挡仍未证明安全，应限制自动模式到无遮挡小块皮肤。
- 状态级 undo/redo 与核心取消已测，不等于实际桌面鼠标、缩放平移、触屏、系统返回、中断恢复等 UI 交互已验收。
- 真实痘痘、密集斑点、皱褶、大范围泛红、严重低光/模糊、复杂妆容与多肤色质量没有充分数据；本轮不作通过声明。
- 手工工具是经典像素/形变/补片算法，不是学习型生成修图，不替代待接入的学习型精修。

## 2026-10-22 曲线/HSL与透明输入保护增量

当前独立套件88/88，0失败、0跳过。新日志`independent-tests-with-tone.tap`、新哈希`tone-tested-source-hashes.json`。包含原62项、新增透明输入保护3项、调色核心20项、调色流水线3项。旧62项报告与旧哈希只作为历史快照。

- 非全不透明输入液化：alpha为0、128或254，即使在远离笔刷处，也在Worker/native拒绝；实际透明PNG导出同样拒绝，原图不改。透明输入仍允许只设选区和显式取样clone。此保护不等于alpha随液化变形。旧0.2.0安装包的裁边缺陷不能被本源代码通过结果掩盖。
- 五点曲线与八色HSL：独立闭式值验证主曲线先于通道曲线、总强度只融合一次；单调和显式自由曲线、灰阶/色相环绕/原始色相权重、隐藏RGB/alpha、输入不可变、取消及精确/近似直方图均通过。
- 流水线：basic tone → advanced tone → local layers顺序、Worker/native一致、真实PNG编解码像素一致、项目配方隔离与非法输入拒绝。全局advanced tone不自动变成选区调色。
- `tone-public-portrait-contact.png`已目视检查：同一公开NASA肖像普通中等曲线/HSL，没有额外硬边或几何变化；不是学习型美颜或各人群美学评价。`tone-synthetic-ramps-contact.png`为明确合成渐变。相邻色带施加强反向色相偏移会按定义压缩部分颜色层次，不能承诺极端无色带。参数见`tone-visual-evidence.json`。
- 直方图是透明度加权的渲染预览/码值统计，不代表RAW裁切、物理亮度或高光可恢复性。仍缺色阶、可选颜色、三向分级、RAW/16-bit/ICC。
- 本报告不含真实浏览器、Windows/4060、Android WebView/触屏操作验收，也不因为自动测试数量而证明全部功能或SOTA。
